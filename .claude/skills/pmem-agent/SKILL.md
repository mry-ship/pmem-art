# `/pmem-agent` — 总控

玩家没点名具体技能时走这一条。玩家已经点名界面、图标、合成梯、原画、克隆、变体、镜头包、锁风格、审图、归档或教练时，直接读那一支，不要再绕这里。

总控自己不生图、不审图、不归档。需求定稳才做第二段。定不稳就打回，不往下做。

## 第一段 · 把需求定稳

固定 2 轮。第 2 轮查合理性、缺漏和理解错误。

每一轮单独开一个子 agent。交给它的只有三样：玩家原话、全部附图、上一轮写下的那一句需求。第一轮没有上一句。

第 1 轮写出整句。这一句要写明交付物是什么、每张图锁什么、每张图不锁什么。写不清的地方标成「还不确定」，不要替玩家挑一个。

第 2 轮对照玩家原话和全部附图，检查第 1 轮三件事：合不合理，漏了什么，有没有理解错。漏的补上。理解错的按原话改回来。合不合理是看这句话能不能和原话、附图同时成立。不能同时成立、又不能从原话里改回来的，标成「还不确定」，不要替玩家挑一个合理的。改完交回一整句。

第 2 轮这句里面没有「还不确定」，并且玩家的话和附图对得上，这句就是定稿，进入第二段。

第 2 轮还有「还不确定」，或者话和图对不上，停在第一段，不进入第二段，不生图，打回给玩家一起矫正。

每一轮的句子都写给玩家看。定稿是第 2 轮。

打回时只写三行：每一轮的需求句、还不确定的是哪一处、需要玩家拍板的那一个问题。一次只问还晃的那一处。玩家答完，从第一段再开，不接着往下猜。

子 agent 用当前环境的子 agent。Cursor 里用 Task。没有子 agent 时，同一条对话里仍按轮写，停和打回的条件与上面相同。不要把两段并成一次口头分流。

## 第二段 · 交给一个 agent 去选

再开一个子 agent。交给它的是三样，缺一不可：

1. 定稿那一句，以及第一段每一轮的句子。
2. 每一张图的路径。不能在交出去之前收成一张。
3. 下面这些技能文件，让它自己读全文，不要靠记忆复述：
   - `.cursor/skills/pmem-draw/SKILL.md`
   - `.cursor/skills/pmem-ui/SKILL.md`
   - `.cursor/skills/pmem-icon/SKILL.md`
   - `.cursor/skills/pmem-merge-ladder/SKILL.md`
   - `.cursor/skills/pmem-style-lock/SKILL.md`
   - `.cursor/skills/pmem-critique/SKILL.md`
   - `.cursor/skills/pmem-atlas/SKILL.md`
   - `.cursor/skills/pmem-coach/SKILL.md`

它按读到的现稿选一支，只执行那一支，并写明交给哪一条、按哪一节。总控不在候选里。父级把这句选择原样写给玩家。

执行那一支时，定稿和每一张图一起带上。会 `converge start` 的，`--reference-image-paths` 写上每一张图，第一张是宽高比要对上交付物的那张，其余按定稿顺序跟在后面，一张不删。`--ref-image` 可以是其中一张，不能把其余的图从列表里拿掉。`--ref-analysis` 按每张图的分工写。`--aspect-ratio` 按交付物写。身份图宽高比不同，也不从列表里删。生成轮若只能垫一张，垫宽高比对齐的那张；打分时仍把成图和每一张参考图按定稿并排看。

选中的技能会 `converge start` 时，启动后先把第一段每一轮用 `converge discuss` 记进同一会话，再开始那一支自己的步骤。过程板上会留下需求是怎么定下来的。

## 交给玩家的结论

需求打回时，回复停在第一段的三行，不写选择，不写过程板。

需求定了并执行了，按这个顺序写：

1. 第一段每一轮的需求句，并标出定稿是哪一轮。
2. 第二段选了哪一支、按哪一节。回显一句「按 XX 走了」，这句只说明选了哪一支。
3. 那一支自己的结算，格式不改。出图的仍是：参考图分析；每一轮出图（图、五维、总分、这一轮改了什么、还差什么）；过程板；总结。总控不另写一套。
