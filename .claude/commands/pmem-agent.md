# `/pmem-agent` — 总控

玩家没点名具体技能时走这一条。玩家已经点名界面、图标、合成梯、原画、克隆、变体、镜头包、提示词、锁风格、审图、归档或教练时，直接读那一支，不要再绕这里。

总控自己不生图、不审图、不归档。一轮审核列完分析，才决定进不进第二段。路径、版式、命名这类可默认项写进分析，不要当成多种情况。

## 第零段 · 标准路由句 + 强制本地路由（禁止盲猜）

本地匹配是**字面 n-gram + 口语扩展**，不是向量语义。美术口语多时，必须先写成**一行标准路由句**，再进 `route`。
**附图可选**：玩家可以只打字不附图；有附图要写清用途。无图时标准句不要硬写「有参考图」。变体对照表见 `docs/route_pipeline.html`。

### 0.1 先写标准路由句（Agent 必做，写入分析）

用固定模板词，一行即可（可抄 `skills_kit/route_normalize.py` 里的 `CANON_TEMPLATES`）：

| 意图 | 标准句示例 |
| :--- | :--- |
| 普通图 | `要画一张图；有参考；题材不变；走普通图` |
| 克隆 | `有参考图；换新题材；锁画风；走克隆` |
| 变体 | `同一身份；换表情或动作或画风；机位已在图上；走变体` |
| 多图分工 | `多张附图各管一件事；走多图分工` |
| 镜头包 | `要几套机位给玩家挑；先不出成图；走镜头包` |
| 界面 | `整套界面或 HUD 或九宫格与状态族；走界面` |
| 图标A/B/C | `1024 桌面启动图标；走图标A` / `线性 SVG；走图标B` / `背包透明底；走图标C` |
| 合成梯 | `同一套东西一档比一档大；走合成梯` |

**⚠ 风险**：标准句写错会带偏检索；若与原话规则冲突，`route` 会报 `plan_conflict` 并降为 `confidence=low`，必须停下来问人，禁止硬执行。

### 0.2 再跑本地 route

```bash
python3 pmem_art.py route --text "<玩家原话>" --canonical "<标准路由句>"
```

有附图时加 `--image <路径>`（可多次）；有身份/结构分工时加 `--role identity` / `--role structure`（与 `--image` 顺序对齐）。Agent 自用加 `--json`；**给美术看时只用输出里的 `artist_say`**（或 `route --brief`），禁止把 confidence / neighbors / json 刷给画师。

- **禁止**只靠通读长 SKILL / 注册表散文来猜路由。
- **禁止**把 `route_bank` 整库或上千条话术贴进上下文。
- **对美术只贴 `artist_say`**（已含 banner + 一句人话或「先问你一句」）。
- `execute_ok=true`：写步骤表并执行；随后才能 `converge start`（无 route 缓存会被闸门拦住；调试才允许 `--skip-route-gate`）。
- `confidence=ask` / 糊话门 / `plan_conflict` / `mode=stop`：先问美术，**禁止默默走普通图开画**。
- 点名了 `/pmem-ui` 等：仍建议跑 `route` 写入闸门缓存；**点名锁定**不改判。

白话流程图：`docs/route_pipeline.html`。重建库：`route --rebuild`。用户正负例：`.memory-art/route_bank/user.jsonl`。

## 第一段 · 一轮审核

只审一轮。这一轮写明交付物是什么、每张图锁什么、每张图不锁什么，并查合理性、缺漏和理解错误：合不合理，漏了什么，有没有理解错。漏的补上。理解错的按原话改回来。合不合理是看这句话能不能和原话、附图同时成立。

不要再开第二轮去复查。分析列给玩家看。没有子 agent 时，同一条对话里仍按下面停和执行。不要把分析和执行并成一句口头分流：分析先写出来。

### 默认 vs 硬不确定（防卡死）

| 种类 | 怎么处理 | 例子 |
| :--- | :--- | :--- |
| **可默认** | **必须写入分析**，用「默认：…」标出；**禁止**标成「还不确定」来打回 | 新 HTML 路径/文件名、对比页版式、说「再跑一遍/对比」时默认与旧展陈**同范围**、旧案已有 ref 且本趟仍是同类任务时默认垫同款 ref、输出目录用并列新文件夹 |
| **硬不确定** | 这才是多种情况，列出来等确认 | 交付物类型互斥（到底是 UI 套件还是单张插画）、身份/题材对错会做成另一张图、话与附图直接矛盾且无法从原话改回、多套互斥题材里必须玩家挑一个、图标 A/B/C 同时命中、`route` 的 confidence=low |

能默认的当场写进分析。不要把「玩家没写成绝对路径」当成多种情况。

### 审完怎么走

1. **只有一种确定情况**：把分析列出来（含默认项），然后直接执行第二段。不要再等确认。
2. **多种情况**：把每一种列出来，停，不执行。一次只列这一处。等玩家确认其中一种，再执行。
3. **玩家没有选上面列的情况，而是另提要求**：按新原话重新审核一遍。这一遍不论最后是确定还是仍有多种，都先列出来，等玩家确认，确认后再执行。不要在重审的同一轮里直接执行。

确认之前不生图。玩家只是选了已经列出的一种，不用再审一遍。

## 第二段 · 总控对表，再交给一个 agent 执行

总控自己对表。子 agent 不另选技能。玩家已经点名的那一支，按点名走，注册表不改判。

先用第零段的 `route` 结果（`plan`），再读 `.cursor/skills/registry.md` 核对 heading。定稿前后要交的东西不一样，就拆成多步，每步单独对一次。对表按 `phase` 从小到大，停在第一条命中的、`routable` 为 true 的行。普通图排在最后，只是兜底：

1. 先跑 `tighten`，顺序与表里一致。有参考但没说新题材，停在普通图。没人要几套机位，不进镜头包。关、开的机位和身份不在同一张图上，停在多图分工。单张弹框、单张图标，不升成整套界面或图标集。
2. 再用 `when` 对这一步。整屏、HUD、九宫格、按钮状态族进界面。桌面 1024 进图标 A，一套线性 SVG 进图标 B，背包 64/128/256 进图标 C。A/B/C 同时命中就停下来，只问这一处，不替玩家挑。同一套东西一档比一档大，进合成梯。
3. 「以后按这张画」进锁风格。「只审、不画」进审图。「散图归位」进归档。进步、短板、知识卡只有玩家这句话里要看时才进教练。要写提示词、先不出图，进提示词。
4. 以上都没对上，用普通图那一行。
5. 定稿写明两张参考的像素必须同时出现在同一张成图里：只接受 `simultaneous_pixels: true` 的行。现在没有这种行，就停，写明原因，不改派到多图分工，不开始出图。

局部修、设定表、分镜、姿势锁、同一场景换光、画幅延展、放大清稿、序列帧、平铺贴图、带字主视觉、字标、色板点选、情绪板，注册表里没有这些节。对不上就写「没有识别到可用技能」，停，不开始出图，也不改走普通图。不另编一节。透明底、表情表、拼板、远中近、镜头包点选后的机位、审完再改，落在已有的普通图、变体、多图分工、镜头包、审图那几行里，不新开技能。

命中之后，在该文件里查找这一行的 `heading`。标题里的反引号可以忽略，文字对上即可。找不到，注册表过期：停，写明要跑 `python3 pmem_art.py skills --install`，不用过期的那一行出图。

对上之后先写步骤表，再执行。步骤表是告知，不再开一轮点选。简单任务一行，写完就执行。每一步只走一支。下一步拿上一步交出来的图。上一步没做完，下一步不开始。每一行写全这六样，缺一样这步不能开始：

1. 用哪一支、哪一节
2. 这一步交什么
3. 垫哪张，不垫哪张
4. 锁什么
5. 怎样算做完（生图步：≥9.5 或满 4 轮；展陈 HTML 还要 `python3 pmem_art.py showcase-gate --html <路径>` 通过）
6. 交给下一步什么

回显以 `route` 的 `banner` 为准（最前一行）。例如「【按 多图分工 走了】」「【走默认路径】按 普通图 走了」「【按 Mode A 走了】」。这句只说明选了哪一节，不问选哪条技能。

前面的行都没对上、而这句就是要画一张：走普通图，banner 必须带 **【走默认路径】**。单张、`medium`、最多 4 轮、合格线 9.50。多张图留在参考列表里，生成只垫宽高比对齐的那张。这一行不说成多图分工。普通图这一行本身不可路由，或注册表里找不到它的标题：写「没有识别到可用技能」，停，不开始出图。

多图分工的关、开写成前后两行。第一行身份图和结构图都垫上，身份图原来的机位作废，开会话用 `converge start --contract split`，不要写 `--scale medium`。下一行只垫已经通过的那张，只改这一态。

再开一个子 agent。交给它的只有命中的那一节，不是八份全文。三样缺一不可：

1. 这一轮列出的分析，加上这一步的六样。
2. 每一张图的路径。不能在交出去之前收成一张。
3. 这一行的 `file` 和 `heading`。只读这一节。

它按这一节执行。总控不在候选里。父级把 `banner`（含【走默认路径】或【按 XX 走了】）原样写给玩家，放在结论最前。

- **普通单交付**：只执行一支。
- **定稿写明是「整页展陈 / 对比页 / 多技能同范围重跑」**：按定稿清单**依次点名**调用对应技能（每次一支、做完再下一支），最后收成新 HTML；不要因为清单里有多项就打回重问范围。

执行会生图的技能时，定稿和每一张图一起带上。会 `converge start` 的，`--reference-image-paths` 写上每一张图，第一张是宽高比要对上交付物的那张，其余按定稿顺序跟在后面，一张不删。`--ref-image` 可以是其中一张，不能把其余的图从列表里拿掉。`--ref-analysis` 按每张图的分工写。`--aspect-ratio` 按交付物写。身份图宽高比不同，也不从列表里删。生成轮若只能垫一张，垫宽高比对齐的那张；打分时仍把成图和每一张参考图按定稿并排看。

定稿写明两张参考的像素必须同时出现在同一张成图里：注册表里没有 `simultaneous_pixels` 为 true 的行，就停在这一步，写明原因，不改派到多图分工，不开始出图。

选中的技能会 `converge start` 时，启动后先把这一轮分析用 `converge discuss` 记进同一会话，再开始那一支自己的步骤。过程板上会留下需求是怎么定下来的。多技能依次跑时，每一支用自己的会话；对比 HTML 在全部完成后写。

## 交给玩家的结论

多种情况还没确认，或另提要求后的重审还没确认：只列分析，不写过程板，不执行。

已经直接执行，或玩家确认后执行了，按这个顺序写：

1. **最前一行**：`route` 的 `banner`（【走默认路径】或【按 XX 走了】或【路由停】）。
2. 这一轮分析。标明是确定后直接执行，还是确认后才执行。若用了路径/版式类默认，列一行「本趟默认：…」。
3. 第二段选了哪一支（或依次哪几支）、按哪一节；步骤表六样。
4. 那一支自己的结算，格式不改。出图的仍是：参考图分析；每一轮出图（图、六维、总分、这一轮改了什么、还差什么）；过程板；总结。总控不另写一套。整页对比时最后给出新 HTML 路径。
