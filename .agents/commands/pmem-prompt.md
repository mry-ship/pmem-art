# `/pmem-prompt` — 提示词生成器（按类型分流）

玩家要「帮我写提示词 / 把这句话写丰满 / 给我几套 brief 选」时走这一条。**本技能不生图、不跑 converge。** 交出去的是给玩家挑选或再改的提示词方案。

玩家点名了界面、图标、合成梯、原画、克隆等并要直接出图时，不要用本技能代替那一支；可以先用本技能出方案，玩家点选后再交给对应生图技能。

## 输入

- 玩家原话（必有）
- 附图（可选）：有图就先看图，写清从图里锁什么、不锁什么
- 目标类型（可选）：玩家写明了就用写明的；没写则你必须先判定（见下），判定不稳就先问一句，不要混用另一类的句式

---

## Step 0 · 先定类型（必做，写进回复第一行）

用一行写出：**判定类型：`…` · 依据：… · 将交给：`/pmem-…`**

| 类型码 | 怎么认 | 交给 |
| :--- | :--- | :--- |
| **普通图** | 单张插画/气氛/道具静物，没说整套 UI、没说升级梯、没说换题材克隆 | `/pmem-draw` |
| **原画 / Key Art** | 主视觉、Key Art、概念气氛、宣传立绘、无操作控件的大场面 | `/pmem-draw`（原画合同） |
| **克隆** | 有参考且说「按这风格画新题材 / 锁画风换主体」 | `/pmem-draw`（克隆合同） |
| **变体** | 同一身份，只改表情/动作/小道具/局部 | `/pmem-draw`（变体合同） |
| **镜头包** | 同一主体要几套机位/景别可选 | `/pmem-draw`（镜头包；点选前不生图） |
| **UI / HUD** | 主菜单、弹窗、九宫格、按钮态、整屏 HUD、商店截图级界面 | `/pmem-ui` |
| **图标 A** | iOS/Android 桌面启动图标、App Icon 1024 母版 | `/pmem-icon` A |
| **图标 B** | 线性 SVG 导航/功能图标集 | `/pmem-icon` B |
| **图标 C** | 游戏背包道具格、透明底栅格图标 | `/pmem-icon` C |
| **合成梯** | 同域 L1–L8 升级链、一档比一档大 | `/pmem-merge-ladder` |
| **锁风格 brief** | 只要色板/光影/禁用词文字规格，不求出图 | `/pmem-style-lock`（或先出文字再锁） |

认成 UI / 图标 / 合成梯时：**禁止**用普通插画句式交差。类型在「原画 vs 普通图」「图标 A vs C」之间晃，先问玩家，不要猜完就出 4 套混类方案。

---

## Step 1 · 按类型用专属清单扩写

公共底线（每类都查，缺则补；已钉死标「玩家已锁定」）：

| 维度 | 要写清 |
| :--- | :--- |
| **合理性** | 主体/控件/档位关系能不能成立；矛盾处标「还不确定」或互斥选项 |
| **美观 / 构图** | 景别或布局分区、主体占比、留白/满幅、安全边 |
| **画风 / 媒介** | 具体媒介与色板角色；禁止「好看的」空词 |
| **光影** | 主光方向与色温、环境光；用具体名词 |
| **材质与边缘** | 金属/布/釉/纸纹/描边软硬——按类型取相关项 |
| **禁忌** | 正向句写不要什么 |

下面按类型**加码**（该类方案必须覆盖；用该类句式，不要串味）：

### 普通图 / 原画
- **景别叙事**：特写锁什么器官/零件；中景/全景锁近中远哪一层是主体
- **原画加码**：史诗或商业完成度、空气透视、主视觉记忆点一句话；无 UI 控件、无可读乱码字
- 方案差异优先落在：机位 / 光色戏剧 / 媒介笔触——不要三套都改成「更精致」

### 克隆
- **锁什么**：媒介、色板、笔触、描边、光影法则（从参考读出）
- **不锁什么**：构图、题材、身份（除非玩家要保留）
- **新题材一句说清**：新主体是什么、在干什么
- 方案差异优先落在：新题材摆法 / 借多少参考光色——不要改成「换画风」

### 变体
- **身份锚点**：性别物种年龄段、发型服色、脸型——全部写死
- **只改清单**：表情/手指/小道具/披风角等，一条条列出
- **禁止改**：机位、画风、身份
- 通常极确定 → 常为 **1 套**；能分叉时只分「改哪一项」

### 镜头包
- 每套 = **一个机位方案**（景别 + 机位名词 + 主体占比）
- 身份与画风全套共用，写在总述里，不要每套重复改身份
- 点选前注明：选字母后再生图

### UI / HUD
- **屏幕类型与画幅**：主菜单/弹窗/HUD；16:9 / 竖屏等
- **布局分区**：顶栏 / 中央内容区 / 底栏主钮 / 侧栏
- **九宫格**：中心是否大块留白可拉伸；角花是否锁在角内
- **控件清单**：主钮几枚、状态族（normal/pressed/disabled）、资源珠等
- **材质语言**：描边层数、釉/金/木；**商业密度**（上架截图级）用具体名词
- **禁忌**：无可读乱码字；内容区禁止塞道具插画；勿用单张插画句代替整屏
- 方案差异优先落在：布局疏密 / 材质冷暖 / 主钮造型——不要三套都只换形容词

### 图标 A（App Icon）
- 满幅直角母版；核心符号落在 **72%–80% 安全区**
- **单符号**高识别；小尺寸可读；无字、不烤圆角遮罩
- 微立体：底板渐变 / 主体体块 / 顶缘高光
- 方案差异：符号隐喻不同，或浅/深底板——不要画成风景插画

### 图标 B（SVG 集）
- 清单（home/settings/…）、统一 viewBox / stroke / linecap
- `currentColor`；视觉重量与 padding 一致
- 方案差异：线型粗细预设或圆角语言——输出的是规格句，不是一张插画

### 图标 C（道具格）
- 1:1、厚剪影、透明友好暗底；棚拍主光；零件可读
- 方案差异：同道具的装饰多寡 / 稀有度感——不要画成场景插画

### 合成梯
- **第一段是关系稿不是出图句**：八行升级链 + 一句画风
- 每档：单件居中、`parts_add` 具体零件、体量只大一圈
- 方案差异：升级叙事分叉或画风一句分叉——不要直接交八张插画 prompt 冒充关系定稿
- 写明：说通后再一档一张正方形交给 `/pmem-merge-ladder`

### 锁风格 brief
- 主辅点缀 HEX、光影法则、笔触、禁用词
- 不写生图构图；交给 `/pmem-style-lock` 或仅作文字规格

## Step 2 · 输出格式（固定）

1. **类型行**（Step 0 那一行）
2. 两三行复述：听懂的交付物、已锁定、还晃的点（晃的若影响类型，先问）
3. 方案：
   - 默认 **2～4 套**（须同属已判定类型；禁止 A 套 UI、B 套插画这种混类）
   - 每套：**方案名**（≤四字）· **中文目标句** · **英文执行句** · **本套侧重** · **相对原话改了什么** · **建议交给：`/pmem-…`**
   - 变体/锁死 brief 等极确定时只出 **1 套**，并写：「只有一套：因为……再拆会和原话冲突。」
4. 问玩家：选字母，或补充/改口（含「其实我要的是 UI 不是原画」这类改类型）。**点选前禁止开生图。**

## 怎么用（复制即用）
```text
/pmem-prompt 青瓷小猫，帮我写成能直接生图的几套说法
/pmem-prompt 原画：浮空遗迹黄昏 Key Art，给我 3 套机位与光色分叉
/pmem-prompt [附图] 克隆：锁这张画风，题材换成白兔抱胡萝卜
/pmem-prompt UI：青瓷金主菜单，上架截图密度，扩成可交给 /pmem-ui 的完整目标句
/pmem-prompt 图标A：天穹浮城 App Icon 母版，几套符号隐喻
/pmem-prompt 合成梯：治疗药八档升级，先写关系稿几种叙事
```

## 禁止

- 不生图、不 `converge start`
- 不把多套方案收成一张「平均提示词」交差
- **不混类型**：未判定或判定为 UI 时，禁止交普通插画 prompt；反之亦然
- 不编造玩家没给的身份锚点（发色瞳色等）；缺了标「还不确定」或做成选项
- 不写「加强氛围 / 提升质感」这类空话当方案差异
