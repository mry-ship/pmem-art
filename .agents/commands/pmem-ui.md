# `/pmem-ui` — SpriteCook 式 UI Kit / HUD / 九宫格整套生成

只在玩家点名界面，或 `/pmem-draw` 判成「界面」之后执行。不要用单张插画合同代替这套管线。

## 怎么用（复制即用）
```text
/pmem-ui 青瓷幻想主菜单 16:9：可九宫格空内容大面板、顶栏纹章细金线、底栏三枚异形主钮（开始/续关/设置）带体积与接触影、侧栏资源珠；统一青釉+暖金材质，无可读乱码
/pmem-ui 蒸汽朋克战斗 HUD 透明底：血条空/满、四技能槽冷却态、左下小地图框；黄铜铆钉+雾玻璃，控件密度上架级
/pmem-ui [拖入概念图] 按概念拆出：主面板九宫格切线、主按钮 normal/pressed/disabled、进度条空满、Tab 选中/未选中；材质描边跟概念锁死
```

## 原理（截图摘要）
1. `search` 召回 `ui.*` 红线与定稿 → 2. **概念先行** → 3. 透明组件表 → 4. 九宫格 + 状态族 → 5. **强制 4轮 ≥9.6**（每轮展示评分履历） → `finish` 打印履历 + **记忆静默写入**（勿旁白记忆）

你现在运行在 **pmem-art UI Kit 模式**（对标 SpriteCook UI Kit Builder：概念先行 → 组件表 → 九宫格切线 → 状态族）。**禁止**把整屏各控件零散各生一张再硬拼；必须先锁一个统一视觉语言的概念稿，再从同一概念抽出可复用零件。

---

## 一、适用场景
- 主菜单 / HUD / 暂停 / 设置 / 背包 / 对话框 / 商店 / 任务日志 / 角色面板 / 地图 / Game Over / Overlay
- 需要 **九宫格可拉伸面板、按钮多状态（normal/hover/pressed/disabled）、进度条空满态、标签选中/未选中** 的成套 UI

## 二、标准流水线（Concept → Sheets → 9-Slice → Converge）

### Step 0：确定屏幕类型与规格
确认：屏幕类型、平台（桌面/主机 vs 移动）、画幅（16:9 / 超宽 / 竖屏）、目标模块（如 `ui.MainMenu` / `ui.InventoryHUD`）。玩家写了画幅，或点名了某一块具体的屏，以那一块屏为准。模块里过期的方图规格不能把主界面收成 1:1。
```bash
python3 pmem_art.py search --module <ui.模块>
```

### Step 1：概念先行（Concept First）—— 不可跳过
1. 若用户丢入概念图：先做参考图视觉解构（构图分区、主辅色 HEX、金属/木纹/霓虹材质、控件密度），再进入组件抽取。
2. 若无概念图：先生成 **1 张完整屏幕概念稿**（整屏布局，统一材质与色板），用 `/pmem-draw` 同款 **4轮 >=9.6 收敛** 打磨概念稿：
   ```bash
   python3 pmem_art.py converge start --goal "UI概念稿：<屏幕类型+风格>" --module <ui.模块> [--scale medium|high]
   # 每轮：converge generate 生图，再 converge judge 审图，直到 >=9.6 或满 4 轮
   python3 pmem_art.py converge finish
   ```
3. **概念稿通过后才进入组件表**——不要在概念未锁定时散生按钮。

### 点名了某款产品的主界面
主界面概念不是空心九宫格，也不是关卡棋盘。玩家点名某款游戏的主界面时，可以先看一张该产品主界面的真实截图，只为了把下面八项写进提示词。生图只交这段文字，不把截图垫进生成，也不要照着像素克隆。
- 场景铺满整屏。底栏后面的地面、地毯、墙脚都要写出来，控件叠在场景上，不要写成一条与场景断开的空托盘。
- 不要把主界面改成另一块屏：家园不要画成三消盘面，也不要画成中间留白的装饰框。
- 九宫格和组件表等这张主界面概念锁定后再拆。中心是场景时，不要求中心留白。

### 复刻先写八项，再出第一张
风格、结构、六维写清楚之后，后面的轮次才稳。八项里还有「精致」「高级」「类似某游戏」这种空话，就不出图。

1. **渲染品类。** 一句话写死是哪一种：玩具塑料、商业三渲房间、扁平矢量，或写实。再写三条它不会变成的样子。
2. **镜头与裁切。** 机位角度、远近、画面切掉哪几边、地板还剩多少。
3. **分区与叠层。** 从上到下、从左到右各占什么；哪件压在哪件上面；场景道具和界面图标分开写。
4. **色彩面积。** 哪块颜色占哪一块区域，各大约多少，带 2～3 个锚色。不要只丢一串色号。
5. **材质分工。** 木、纸、织物、金属、按钮各用什么高光。禁止全画面同一种塑料，或同一种木纹。
6. **体量与疏密。** 哪件是小摆件，哪件铺满墙，哪块空地不允许出现。
7. **控件工艺。** 每一类控件写形状、描边颜色、上下深浅、顶高光、投影、字重、是否被屏幕切边、是否互相重叠。
8. **文案。** 必须出现的字，以及不许出现的标签。

界面打分在原来五个名字之外加上无瑕疵，每维写 0–10。无瑕疵盲评。正式分是加权调和平均，无瑕疵占 25%。浅色一版、深色一版在概念稿锁定后各跑各的。单张空面板仍走克隆。
1. **风格色板**看第 1、4 项。品类错了，这一维低于 7.5，不能停。
2. **结构**看第 2、3 项。机位退成空舞台、分区错、控件掉进场景中部，低于 7.5，不能停。
3. **光影材质**看第 5 项。
4. **管线合规**看第 8 项：字对不对、有没有多出来的标签、有没有画成另一块屏。复刻概念不查透明底。低于 8.0 不能停。
5. **套件一致**看第 6、7 项：疏密和控件工艺是不是同一套。

下一轮只改没对上的项，对上的项原句留在提示词里。不要整段重写，以免把已经对的顶栏、文案和按钮工艺冲掉。

### 带背景的主界面按模块占位
这类主界面是一层房间背景，加上若干界面模块。先分开出两张，不对只改那一张，两张都稳了才合成到一张上。
- **背景张**只画房间：构图、镜头、画风、疏密。画面里不要出现顶栏、进度条、按钮、底栏、图标和可读文字。底部留出一块空地板，留给以后的按钮。
- **界面张**只画界面，落在一块平的纯色底上，不要再画房间。每一块占自己的矩形，块与块之间留缝。允许的压盖只发生在同一个模块内部，例如进度条左端的书、关卡钮右端的包。
- 左侧入口不压进度条，也不压底部按钮；进度条不压顶栏；两枚主按钮之间留缝，也不压底栏。右侧钥匙留在画面上段，不要掉到按钮旁边。
- 结构分在复刻时同时看这件事：两块界面叠在一起，或钥匙、侧栏掉出自己的矩形，结构低于 7.5，不能停。背景张的问题不拿到界面张里改，界面张的问题也不要重画房间。

### Step 2：从概念抽取组件表（Component Sheets）
以概念稿为垫图/参考，在 **透明底** 上生成组件表（1~3 张 sheet），覆盖：
- **面板 / 边框 / 装饰条**（可九宫格拉伸）
- **按钮族**：至少 normal + pressed（最好含 hover / disabled）
- **进度条 / 血条**：空轨 + 满轨（或分段填充）
- **标签 / Tab**：选中 + 未选中
- **图标位 / 分隔线 / 角花** 等概念中出现或隐含的零件
同一概念参考下批量生成，保证木纹/螺栓/色板/光影角度一致。概念稿和组件表的每一轮都垫最初那张参考（用户概念图，或已定稿的概念稿），不改垫上一轮生成结果，修正只追加进提示词。缺件时只补缺件，不要整套重开。

### Step 3：九宫格切线与清单（9-Slice + Manifest）
对每个可缩放件标注九宫格：四角固定、四边单向拉伸、中心双向拉伸。输出清单建议：
```
ui_kit_<name>/
├── concept.png
├── sheets/
├── elements/          # 透明 PNG 单件
├── manifest.json      # name / group / state / rect / nine_slice {l,r,t,b}
└── preview.html       # 可选：拼装预览
```
`manifest.json` 示例字段：`name`, `group`, `state`, `file`, `nine_slice: {left,right,top,bottom}`, `scalable: true|false`。

### Step 4：关键件二次收敛（可选但推荐）
对主面板、主按钮等核心件，若六维评分 `< 9.6`（重点查：中心拉伸区是否干净、转角是否形变、透明底毛边、状态族是否同系），再跑一轮 `converge generate` 局部重绘，然后 `converge judge` 审图。

### Step 5：沉淀记忆
```bash
python3 pmem_art.py ingest <concept或主面板路径> -p "UI kit <屏幕> 概念/主面板" --apply
python3 pmem_art.py feedback "UI套件色板与九宫格规范：<摘要>" --module <ui.模块> --kind art_decision
```

## 三、界面审图（概念稿和组件表同名五项；管线只做门槛）

风格色板、结构、光影材质、套件一致四项共占 75%，无瑕疵占 25%。缺了无瑕疵不能停。管线合规另记，不进乘积。结构低于 **7.5**，或管线低于 **8.0**，正式分改取该分，不能停。主界面画成空框、三消盘、空舞台或另一块屏，结构必须低于 7.5。点名复刻时品类错了，风格色板同样低于 7.5。

- **概念稿**：点名的那一屏；顶栏、两侧、底栏、主按钮的位置；地面或地毯铺到屏底；控件落在场景上；材质和色板同一套；货架密度；没有可读乱码；该有的字在，不该有的标签没有；不是另一块屏。
- **组件表**：九宫格（角固定、边单向、中心双向）；拉伸中心干净；角不变形；同一套光；木、金属、玻璃同一套；按钮 normal/pressed，有 hover/disabled 也要在；进度空/满；页签选中/未选；装饰、分割、图标槽对上概念稿。
- **管线（只做门槛）**：概念稿 16:9 或 9:16，没有手机外框；组件表透明、无脏边、分辨率对、manifest 有切线。复刻概念不拿透明底当这一维。
- **弹框克隆**：内容区空，不要把参考道具放在正中；顶饰最多一件；底栏只有符号按钮。内容区回声参考主体：正式分不超过 8.85，不能停。

示例：`风格色板8.6/结构8.2/光影材质8.4/管线合规9.0/套件一致8.5`

## 四、最终交付必须包含
1. 概念稿 + 组件表 + `elements/` + `manifest.json`（含九宫格）
2. 若跑了收敛：默认附上全轮次评分优劣总表（不足/改点）；只要终稿用 `--quiet`
3. 已写入 `.memory-art` 的 recipe / redline 路径


## 记忆静默 / 履历可见（Agent 必读）
- `converge finish` 后系统自动写反思/口味/learn 队列——**无需**再跑 `/pmem-coach`。
- 对用户默认展示：**每轮六维分 + 不足 + 改点 + 胜出图 + 全轮履历**；若有「小提示」原样转述（每会话最多 1 条）。**禁止**旁白记忆写入。
- 只要终稿：`--quiet`。教练 / 广度：用户明确要求或进阶技能时再给。
