现象：已有美术库的开发仓再跑 pmem_art.py init，会跳过「已存在 .memory-art」的提前返回，把 config、modules.yaml、candidates.json 重写成 6 个幼龄脚手架。
原因：cmd_init 把 auto_isolated_on_copy 当成「这次仍要冷启动」。
该标记在拷贝隔离后一直留在 active_project.json 里，不会因为 false。
本机 bound_root 已是当前目录，库本身没有被再次隔离。
排除：为刷新技能或升级后对齐，在这份已有画库上跑 pmem_art.py init（即使不加 --force）。
正确做法：刷美术技能和 Windows 入口用 skills --install 或 ensure_cursor_stubs；
刷研发记忆规则用 pmem init --agents auto --hooks auto。
两者都不改 modules.yaml。
