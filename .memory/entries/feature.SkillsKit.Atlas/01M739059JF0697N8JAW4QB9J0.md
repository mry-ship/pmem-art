现象：按 /pmem-atlas 跑 classify-watch --apply 批量入库时，自动模块常把第一张图的 resolution/aspect/max_size 写成 specs；
同 glob 后续不同尺寸或更大体积图会批量 QA FAIL，并产生 scene.R1、ui.05 等弱语义模块名。
影响：validate 变红；旧 recipe 路径因搬家变缺图锚点，需 hygiene detach。
约束：高置信自动搬可以做，但入库后若同模块多分辨率，要把 specs 扩成 allowed_resolutions 并放宽 max_size，清掉误锁的 aspect_ratio；弱语义模块名不要当长期正式域。
证据：2026-11-11 全量归档半程出现数十条分辨率/体积 FAIL，放宽 specs + detach 后 validate 恢复 exit 0。
