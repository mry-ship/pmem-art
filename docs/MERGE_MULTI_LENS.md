# 合成梯 · 多维审稿透镜（通用）

Merge 不是「一档比一档更大更好看」。玩家合两下要爽、棋盘上要认得出、货柜上要像同店货。出图前按下面过；链型说不通先别出图。

**机读过了 ≠ 合理。** `relation-judge` 只查件数/体量/字段；商业标尺与过程类型没钉住，照样会偏成「展陈插画组」。

---

## 0. 对标材料（先决）

- 先看同品类 **真 merge 货柜/棋盘道具**（Merge Mansion / Travel Town / EverMerge 等），不是宣传海报、不是城市建造升级海报。
- 第 1 稿写明：**对标链名 + 档序**（例：EverMerge Wood = Log→Timber→Frame→Building→House→Rich→Grand→Mansion）。
- 抽：**链型、密度/犒赏曲线、过程类型**写进关系稿；玩家未点名画风时，**同一对标再抽品类渲染气质**写入 `surface`。**禁止垫像素抄物件 / 抄构图机位**（气质≠垫竞品截图）。
- 先定 `chain_mode` 与**过程类型**（见 §8），再说通 `merge_why` / `parts_add`，再出图。
- 对标游戏里若城堡/地标是**另一条链或喂养目标**，禁止默默焊成本链末档。

### 0.1 商业优先 · 提案只参考（硬规则）

- **玩家口语是提案，不是锁死档序。** 定链时以同品类顶级竞品「最好、最合理」的货柜方案为准；提案与竞品冲突时跟竞品，并在关系稿写明取舍。
- **档数跟合理，不跟凑满。** 默认常开 8，但若竞品生物/建造段只有 6 档说得通、或必须 9 格才像货柜，按竞品合理档数（允许集内）走；禁止为凑满格发明假档。
- **成长与升级可以混用。** 幼体→成体、同体加 denser 羽/冠/包装、末段数量群/捆扎，只要对标链里有、且合两下可倒推，就可以同链混排（见 §8 A/G 与 §9）。
- **禁止硬凑：** 没有竞品依据的「突然多只堆」「突然金铠换装」「突然另物种」都不算合理。竞品末段若是群/捆，写清对标后可做——那是过程类型，不是硬凑。
- **新鲜感：** 允许邻档微调神态/站姿/头向，增加货柜生动感；禁止借「新鲜感」换机位拼盘或换物种。
- **未点名画风：** 与档序对标**同一竞品系**写入 `surface`。本透镜默认场景是休闲 merge 货柜（软塑胶厚实、棚柔光短接触影、饱和友好、缩略可读、上架完成度）；若对标链/玩家点名是另一渲染系，跟对标链，禁止再盖一层无关软塑胶。关系已对标商业时，禁止回落成无关泛卡通。不是金幻换装海报风；仍禁止垫竞品截图像素。

## 1. 合两下体验（玩家为什么合）

| 问 | 合格线 | 翻车例 |
| :--- | :--- | :--- |
| 合成预期 | 两件同级 → 下一档，说得出「为何变成它」；最好能**倒推**：下一档看起来像两件上一档合出来的 | 「更华丽」空话；装饰换装断故事 |
| 犒赏感 | 低档朴素、高档值得炫耀；**犒赏材质/零件晚出现** | L1 已上红瓦/金边/宝石；全程同密度 |
| 可读进度 | 隔一档也能感到升级 | 邻档几乎双胞胎 |

---

## 2. 棋盘 / 货柜视觉（缩略怎么扫）

| 问 | 合格线 | 翻车例 |
| :--- | :--- | :--- |
| 64px 邻档可分 | 剪影句不能复读；体量缓增 | 只加光点、小饰片棋盘看不见 |
| 单件居中 | 每档/每格一件，无等级字；道具默认无脸；**生物链须有可读眼睛**（竞品同类有脸时） | 场景插画；生物无眼空头；道具乱加脸 |
| 白卡不超框 | overview 圆角卡内整只落幅并留边；冠/尾/翅尖不得切边 | 末档撑破白卡；只涨 `scale_pct` 顶满溢出 |
| 同机位组 | 一链同棚灯同仰角 | 每档换机位像拼盘 |

---

## 3. 档位重要程度（稀有度 / 完成度曲线）

1. **L 低**：原料 / 碎片 / 空壳 / 简包装——只认家族基因，**未完成或廉价**  
2. **L 中**：形态或零件明显升级——`evolve_to` / `parts_add` 肉眼可见  
3. **L 高**：犒赏件——体量最大、细节成块，仍同家族  

曲线要平滑；禁止无过渡跨品类硬跳（糖→奖杯；小屋链→军堡城堡）。

**完成度闸（通用）：**

- L1 禁止「成品感过满」（完整小屋、完整瓶装好货、全套金饰）。  
- 本链的**招牌犒赏材质**（红陶瓦、金箍、宝石芯等）应有**首次出现档**，不要在原料档就给齐。  
- 「框架→封皮」类：下一档必须看得出是**同一骨架填上了墙/顶**，不能看起来像降级成更简陋的无关物。

## 4. 链型合同（上下游）

| 链型 | 通用含义 | 禁 |
| :--- | :--- | :--- |
| `shop_ladder` | 同族形变/同店货（主流） | 强行 `base_body`；糖果默锁 `same_object` |
| `same_object` | 同模只加装 | 礼盒/奖杯换货主语；零件不累计又说不出替换 |
| `species_change` | 同任务域换物种 | 用「禁换物种」口味压过「一组 X」 |
| 轻门（省略） | 未点名链型 | **非糖果**勿默锁 `shop_ladder` |

---

## 5. 颜色与材质

- 锁**家族色相/题材基因**，不是每档换色盘。  
- 介质跟题材：软糖才 SSS；金属/木/陶各写各的。  
- 默认卡通下禁无故产品实拍油光。  
- 材质升级本身可以是进化信号（干草顶→红瓦），但必须落在正确档位。

---

## 6. 整体风格套件

- 一句话 `surface` 锁死整链；`overview_sheet` 可锁白卡深底版式。  
- 无玩家画风 / 无风格参考时：`surface` 必须来自 §0 同一商业对标的**品类气质**，不得另起无关默认。  
- `per_cell` 透明或纯黑隔离，勿白卡冒充逐格成品。  
- 默认交付：整表一组（通常 8 档）；点名逐格才 `per_cell`。

## 7. 出图前最小检查

```
[ ] 已写对标链名+档序（真货柜，非海报）
[ ] 过程类型认对（§8）；链型选对
[ ] 未点名画风时 surface 已写同对标品类气质（非泛卡通回落；未垫竞品像素）
[ ] 关系门 / 五问已过；机读≠商业合理
[ ] 每档 merge_why 或 parts_add 具体，且可倒推
[ ] 体量缓增；64px 邻档可分；overview 每格不超框留边
[ ] 家族基因不断；无装饰换装；无跨链焊末档
[ ] L1 未过满；犒赏材质出现档合理
[ ] 生物链有眼睛（若竞品同类有脸）；未为凑满 N 自创华丽/硬堆群
```

## 8. 过程类型 · 通用合理性（不限「升级展陈」）

先认玩家要的是哪一种 **merge 过程**，再套链型。不同类型的「合理」不一样；用错类型会反复偏。

### A. 同族形变货柜（`shop_ladder` 主流）

- **是什么**：同店同题材，一档换一形态/包装，仍像货柜上一列货。  
- **例**：软糖包装升级；EverMerge 木屋支线；节日气球束。  
- **必须**：家族色/题材锁死；`evolve_to`+`merge_why`；邻档可分；末档仍同店。  
- **禁**：城市建造叙事硬拐到另一 SKU（小屋链焊军堡城堡）；L1 就给满级材质。

### B. 同模加装（`same_object`）

- **是什么**：同一母体，只焊零件/替换可读部件。  
- **例**：药瓶加塞→环→托；吉他加弦→品点→护板。  
- **必须**：`base_body`；每档留母体词；`parts_add` 累计可读（或明示替换式）。  
- **禁**：礼盒/奖杯换货主语；只写「更华丽」；零件缩略看不见。

### C. 同域换物种（`species_change`）

- **是什么**：仍同一任务域，但每档换一种物件。  
- **例**：一组乐器；厨具整表。  
- **必须**：域锁死（都是乐器）；每档仍有合成理由与过渡；整表时勿默锁单母体。  
- **禁**：用口味「禁止换物种」压过玩家「一组不同 X」。

### D. 原料→半成品→成品（建造/组装过程链）

- **是什么**：完成度从「材料/骨架」爬到「可住/可用成品」。常与 A 叠用（EverMerge Wood）。  
- **例**：原木→木料→框架→草棚→瓦屋→庄园。  
- **必须**：低档是原料/空壳；中档封皮；高档才像家/成品；框架→封皮同骨架可读。  
- **禁**：L1 已是带瓦小屋；把「另一条地标链」当成建造末档。

### E. 生产者 / 容器升级（功能件变强）

- **是什么**：主体仍是同一生产者或容器，升级的是产能、格数、外壳完整度。  
- **例**：Merge Mansion 箱柜、工具桶档。  
- **必须**：一眼仍是「那个生产者」；升级读在盖/层/附件，不换物种。  
- **禁**：升着升着变成无关家具或纯装饰奖杯。

### F. 碎片→修复→完整（修复过程链）

- **是什么**：破损态逐步修到完整态。  
- **例**：花盆碎片→破盆→裂盆→整盆。  
- **必须**：破损特征可读且逐步消失；完整态与碎片同家族。  
- **禁**：中档突然换材质家族；完整态认不出由碎片来。

### G. 数量/捆扎过程（堆叠链）

- **是什么**：1→2→捆→堆，主语同类物。  
- **例**：单原木→双原木→木料捆。  
- **必须**：复数与捆扎方式是主进化；不要过早长成复杂建筑。  
- **禁**：从「两根木头」无过渡跳成「宫殿」。

### H. 多轨并列（多条 L1 / 多主题一行）

- **是什么**：一张整表多行，每行一条链。  
- **必须**：轨与轨家族可区分；行内自洽；`overview_sheet`。  
- **禁**：多轨抄成同一剪影；用单轨城堡叙事填所有行。

## 9. 档位不够 / 很长时怎么排（禁止硬凑）

1. **先打开同品类顶级竞品档序**，数清人家怎么从低到高混「生长 / 完成度 / 华丽密度 / 数量群」。  
2. **提案让路给竞品：** 玩家说「别群、改金冠」只是提案；若竞品生物段末段就是群/捆且合两下说得通，跟竞品，并在稿里写对标。若竞品根本没有金铠换装，禁止自创金铠凑华丽。  
3. **说不满默认 N 时：** 优先缩短档数或改用竞品真实混排；其次才在同主语上加竞品确有的 denser 犒赏（羽层/冠形/包装），`merge_why` 仍须具体。  
4. **仍禁止无依据硬凑：** 无对标的多只堆、建筑焊末档、换物种、空话「更华丽」。鸡舍等生产者另链则不要焊进生物段。

## 10. 各过程类型共用的五条铁律

1. **先对标，再自撰**：没有顶级同品类档序，不准开画。  
2. **合两下可倒推**：只看 L(n) 与 L(n+1)，能说出「两件 n 为何变 n+1」。  
3. **未完成→完成**：原料/碎片/空壳在前，犒赏材质与完整成品在后。  
4. **一链一合同**：另链地标/城堡/喂养目标不要焊进本链末档。  
5. **校验别自嗨**：机读 + 自拟五问不够；必须对照 §0 对标档序与 §8 过程类型再判；档不够时对照 §9，禁止数量群/跨链硬凑。
